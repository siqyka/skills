# 会话交接（Session Handoff）

一句话：**交接文档不是会议纪要，而是一份「下一个 agent 读完就能直接动手」的施工图**。它只记录三类东西——已确认的事实、尚未完成的目标、下一步最小行动。其余一切都用路径、命令、行号引用，不复制正文。

**三份参考，按需加载**：`references/handoff-template.md`（写文档时看字段规则）、`references/intake.md`（收到交接文档时读全文）、`references/example.md`（要完整样例时看）。

## 何时用 / 何时不用

**用**：
- 用户说 handoff / 交接 / 生成交接文档 / 传给下一个会话 / 把方案结论写到某个路径
- 会话过长、压缩过多，需要在干净会话里继续
- 任务要移交给别的 agent（subagent、换模型、换工作区）
- 一轮调研或审查结束，结论要交给下游（写报告、改方案、做实现）

**不用**：
- 只是给用户做总结 → 直接在回复里写，别落文件
- 下一个会话真正需要的是产物（代码、报告、表格）→ 先把产物写好，交接文档只给路径
- 跨会话翻旧账 → 用 `session_search` / `search_context`，不写 handoff

## 三种模式

| 模式 | 触发 | 产出 |
|---|---|---|
| **A 生成** | 用户要求交接 | 交接文档文件 + 可直接粘贴的 resume prompt |
| **B 接收** | 消息里带了 handoff 路径或 Handoff 段落 | 先读完文档 → 定向执行，不重走探索 |
| **C 刷新** | 已有 handoff，任务又推进了 | 新编号文件（`-02`、`-03`），不覆盖旧文件 |

## 步骤 1：先全量回扫，再抽事实（不许只写最近几轮）

交接文档的价值是**整个会话的净残值**，不是最近几轮的摘要。最近几轮看得见，所以最容易被当成全部；真正会丢的是开头——原始目标、硬约束、用户否决过的方向、早前定下的决策。**只写后几轮 = 交接失败**。

**1.1 盘点会话边界**

- `acp_status`：列出压缩块（blockId、覆盖范围、主题），先知道哪些内容已经不在眼前
- `get_goal`：objective + 创建时间；目标若演进过，记下路径（最初要 A → 后来改成 B，因为 C）

**1.2 从起点向后逐段扫**

按时间正序一段一段过，每段只回答四件事，登记成「事实时间线」：

| 段（消息 ref / blockId） | 需求或目标变化 | 确认的事实 | 决策 + 理由 | 排除 / 失败 |
|---|---|---|---|---|

- 还看得见的早期消息：直接读
- 已被压缩的块：`search_context` 用该段主题词定位 → `decompress`（不确定就 `full: true`）→ 读原文；**不要拿摘要里的二手结论糊过去**
- 某段确实没有任何残留，才允许跳过，并写一句「该段只有试错，无残留」——这样别人才知道你是判过，不是漏了

**1.3 再补必须现查的当前状态**（不能继承旧结论）

1. **工作区与代码状态**：`pwd`；`git status --short`、`git branch --show-current`、`git log -1 --oneline`；未提交改动的**文件清单**（只列路径，不贴 diff）
2. **目标与任务**：`get_goal` 的未完成 objective；会话里未完成的 todo 项
3. **长任务残留**：`job_list` 里还在跑的后台 job；运行中的 dev server、`ssh_workspace_status` 的挂载与端口转发
4. **产物与外部引用**：PR / issue / 设计文档 / 数据文件的路径或 URL

**1.4 覆盖度自检（动笔前）**

- 会话**第一轮**的用户诉求，在文档里有没有对应的「目标 / 约束」条目？没有就是漏
- 每个压缩块是否至少贡献一条事实，或已标注「无残留」？
- 覆盖不到的区间，在元信息里写 `未覆盖区间：<blockId>`，让接手方知道哪里有缺口——比假装完整好

规则：宁可少写一条，也不要写一条自己没验证过的路径或命令。

## 步骤 2：写文件

**位置**（按优先级）：
1. 用户指定路径 → 照办（相对路径按工作区根解析）
2. 默认：`<工作区根>/_handoffs/<YYYYMMDD>_<主题>-NN.md`，目录不存在就建
3. 工作区不可写（只读、远端只读）或这份交接根本不绑定仓库 → 系统临时目录（`%TEMP%` / `$TMPDIR` / `/tmp`），文件名规则相同

**命名**：`20261113_stock-screener-fix-01.md`。同一主题第 N 轮用 `-02`、`-03`，绝不覆盖上一版。

**绝对路径铁律**：文档内的文件引用、以及回复里给用户的路径，一律写**完整绝对路径**（形如 `<工作区根>\_handoffs\20261113_xxx-01.md`，实际书写时把 `<工作区根>` 换成真实盘符路径，如 `X:\repo\_handoffs\...`），不写 `_handoffs/xxx.md` —— 新会话没有你的 cwd。

**模板**：完整字段说明见 `references/handoff-template.md`，可抄袭样例见 `references/example.md`。最小骨架是七段：

```
# Handoff — <主题>
0. 元信息（工作区绝对路径 / 分支@HEAD / 未提交改动 / 权限模式 / goal / 后台作业 / 端口转发 / 临时文件清单 / 未覆盖区间）
1. 目标（要达成什么 / 为什么 / 明确不做；目标演进过就写演进路径）
2. 已确认事实（按时间线覆盖**从头到现在**：结论 + 依据；决策 + 理由；排除 / 失败）
3. 下一步最小行动（逐条可直接执行，带 path:line）
4. 陷阱与禁区（踩过的坑 + 报错原文；不能碰的东西；失败的尝试）
5. 验收标准（命令 + 预期输出，可勾选）
6. 引用清单（只给路径/URL，不复制内容）
7. 建议使用的 skill 与工具（名字必须真实存在于当前 skill 目录）
```

**去重原则**：凡是已经写在 spec / plan / ADR / issue / commit / diff / 报告里的，只给路径加一句「看哪里」，不复制正文。

**脱敏**：API key、token、cookie、密码、SSH 私钥内容、`~/.dsh/dsh-ssh.json` 里的凭据、个人身份信息，一律替换成 `<REDACTED: 变量名>`，并注明「真实值在原会话或配置文件，不要外传」。

**登记临时文件**：元信息表里加一行 `临时文件（待清理）`，列出**这次交接产生的**文件绝对路径——handoff 文档本身、为梳理现状临时写的脚本、中间导出、落在 `%TEMP%` 的缓冲区。约定：

- 用户要的产物、`引用清单` 里的交付物、git 跟踪的文件**都不算**临时文件，不要列进去
- 一条路径一行或逗号分隔，全部绝对路径；没有就写「无」
- 这一行是接收方收尾时删除清单的唯一依据，漏登记 = 永远没人清理

## 步骤 3：回复用户（必须给出 resume prompt）

写完文件后，回复末尾输出一个可直接粘贴进新会话的块：

```text
读取并接手以下交接文档：
<完整绝对路径>

按文档「下一步最小行动」继续，不要重新探索；文档里的路径、命令、结论视为已确认事实，
与现状冲突时以现状为准并说明差异。
```

同一回复里再给一行摘要：**文档路径 + 它覆盖了什么 + 下一个会话的第一件事**。

**生成端到此为止**：写 handoff 的这个会话只负责登记临时文件，**不在总结里问「要不要删除」，也不删任何东西**——清理是接手方的动作。

## 接收模式（B）：收到交接文档之后

**先读 `references/intake.md` 全文，再动手。** 三条不可省的约束：

1. 一次性读完文档；文档引用的其他文件只按需再读
2. **不重走探索**：不遍历项目根、不「确认技术栈」、不做 Hello World 试验；已有明确路径时禁止广域搜索
3. **读完、动手前用选择弹窗问临时文件清理**——`ask_user_question` 三选项；禁止写成正文问句，禁止先删后问，禁止在生成端问

其余（信任复用、精确补读、对齐当前消息、完成回报、冲突处理）见 `references/intake.md`。

## 红线（任何模式都不许）

1. 留占位符（`<...>`、`TODO`、`{字段}`）——写不出来就删掉该字段
2. 写没验证过的路径、命令或测试结果
3. 把整段源码 / diff / 日志贴进文档（给 `path:line`，如 `src/app.ts:12-18`）
4. 复制已有产物的内容，而不是引用
5. 写「详见聊天记录」——新会话看不到
6. 给用户相对路径
7. 把过期结论当事实（交接前确认 git 状态、文件是否还存在）
8. 编造下一步——没方向就写「待用户决定：A / B」
9. 在生成端（写 handoff 的会话）问「要不要删除」或顺手删文件——清理只属于接手方
10. 接手方不用选择弹窗、改为正文里轻描淡写问一句；或先删后问
11. 未经询问删除任何文件；删清单外的路径；把用户产物当成临时文件删掉

## 自检清单（写完前过一遍）

- [ ] 每个路径都验证过存在（或明确标注「待创建」）
- [ ] 每条命令都能原样执行，且写清了工作目录
- [ ] 没有任何密钥 / 身份信息残留
- [ ] 「下一步最小行动」的第一条，是接手者五分钟内能开始做的事
- [ ] **覆盖到会话开头**：第一轮诉求、原始目标、硬约束都在文档里留了条目，不是从最近几轮才起笔
- [ ] 每个压缩块都交代了去向（写了事实，或标了「无残留」/「未覆盖区间」）
- [ ] 全文没有「详见上文 / 如前所述」
- [ ] 最小骨架的「临时文件（待清理）」已填，且不含用户产物
- [ ] 本次回复里没有「要删除吗」这类清理问句（那是接手方的事）
- [ ] 长度在 100–200 行；超过 300 行说明该把内容外置成产物

## 与其他能力的配合

- **压缩前**：上下文快满时，先出 handoff 再压缩，避免压缩把要写的事实抹掉
- **subagent**：给 subagent 的 prompt 用同一套「目标 / 事实 / 下一步 / 验收」，写短一些即可
- **定时任务**：接力长任务时，交接文档放工作区，任务 prompt 里给绝对路径
- **goal**：交接文档的「目标」段与 `get_goal` 的 objective 对齐；新会话继续同一目标就 resume，不要新建
- **审查 → 修改链路**：审查类 handoff 追加「审查发现」段（问题 / 严重度 / 涉及文件绝对路径 / 建议处理），修改后的方案编号顺延，并在元信息标注「基于审查报告 vN 修改」
